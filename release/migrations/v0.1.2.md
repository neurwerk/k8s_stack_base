# Platform v0.1.2

## Support

- Stable upgrades: Fresh installation only.
- Supported alpha source revisions: `dbcac5d1b3069edd5bb65dd57df95dccfba1f6d1`.
- Downgrade: Unsupported.

## Prerequisites

- Independently verify that the target is empty or is a replacement
  environment. This release does not support an in-place stable upgrade.
- Install every prerequisite and CRD version in `release/manifest.yaml`,
  including Agentgateway CRDs 1.5.0 and openbao-stack-setup 0.2.11.
- Authenticate the platform release signer fingerprint independently and
  provision the public `k8s-stack-release-trust` material outside Git.
- Stage the client-owned model catalog, complete model pricing, Dify default,
  local PII fallback, and required non-secret values before selecting the tag.
- Verify that OpenBao can deliver the application and usage-database fields
  required by the enabled products without exposing their values.

## Client Actions

- Select exact signed tag `v0.1.2` with Flux tag verification and
  `k8s-stack-release-trust`.
- Set `platform.neurwerk.com/adoption-target: v0.1.2` and
  `platform.neurwerk.com/adoption-mode: fresh-install` only after independent
  empty-target approval.
- Compose `client-openrouter-catalog-values` for AgentGateway, Keycloak, the
  API-key bridge, and LibreChat, and compose `client-model-cost-catalog` for
  AgentGateway.
- Configure `frontendDify.defaultModel`, the matching explicit Dify model role,
  `guardrails.llmPolicyEngine.localTarget`, and matching PII routing.

## Breaking Changes

- Base no longer supplies concrete OpenRouter models, pricing, a Dify default,
  or a local fallback identity. Enabled clients must provide those inputs.
- Model pricing must cover every selected, direct, and local model. Missing or
  overlapping pricing and invalid effective catalogs fail rendering.
- The effective model catalog is limited to 256 destinations and 16,384 bytes
  of compact PII metadata. Composed Keycloak access-group JSON remains limited
  to 120,000 bytes.

## Stateful And API Effects

- Fresh installation creates the configured Kubernetes, PostgreSQL, object,
  and secret-backed application state; no existing state migration is claimed.
- AgentGateway records metadata-only request usage in a dedicated operations
  PostgreSQL database. Studio queries it through the private AgentGateway admin
  listener and does not receive database credentials.
- LibreChat uses one generated effective model list for grouped selection and
  endpoint validation. A configured hard default applies to new chats.
- AgentGateway extProc 0.1.3 preserves provider response bytes for PII-disabled
  models under full-duplex response processing.

## Pre-Deployment Checks

1. Verify the target is empty or a reviewed replacement and that no previous
   persistent state will be overwritten.
2. Verify the signed tag, release manifest, migration document, immutable image
   pins, prerequisites, and time-bounded exceptions.
3. Render the complete client composition and verify the model catalog, pricing,
   Dify default, local fallback, PII routing, and access-group grants.
4. Verify required DNS, certificates, storage classes, OpenBao providers, and
   externally provisioned public trust material.
5. Confirm that no unsupported optional package is composed.

## Post-Deployment Checks

1. Verify the Flux source resolves exactly to signed tag `v0.1.2` and every
   required Kustomization and HelmRelease becomes Ready.
2. Inspect non-normal warning events and affected logs without exposing secret
   values or sensitive request content.
3. Verify Keycloak roles, API-key validation, Dify's explicit model, LibreChat's
   grouped model list and default, local PII rerouting, and MCP authorization.
4. Exercise streaming and non-streaming model requests and confirm complete
   usage and pricing metadata through the authorized Studio path.
5. Verify PostgreSQL, object storage, certificates, and secret synchronization
   before making the environment available.

## Recovery

Recovery classification: Replacement restore.

If installation fails or integrity is uncertain, keep the target unavailable,
discard the failed replacement environment, and restore a verified replacement
from reviewed configuration and applicable backups. Re-provision external
trust and secret material through their documented custody procedures, then
repeat every pre- and post-deployment check. A Git revert does not restore
Kubernetes, database, object, or secret state.

## Exclusions

- Stable upgrades and all downgrades are unsupported.
- LibreChat RAG and Code Interpreter packages remain excluded.
- The reviewed LibreChat development-image and DocumentDB privilege exceptions
  remain recorded with their existing expiry dates in `release/manifest.yaml`.
- This release does not activate a client, provision credentials, contact a
  cluster, or authorize Flux reconciliation.
