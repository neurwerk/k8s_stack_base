# v0.3.32 compatibility

## Support

- Stable upgrades: Supported.
- Supported alpha source revisions: `25ee6c19e0921f78c4cd2e0ffb2c2abf48f9a54c`.
- Downgrade: Unsupported.

## Coordinated cutover

Use one maintenance window to adopt the reviewed Base revision, matching service images and caller changes. Use the setup source required by the release manifest before reconciling the selected add-ons; new callers require exact Base prerequisite `0.3.32`.

Default model and MCP endpoints authenticate with `Authorization`. Override endpoints use `Authorization-Neurwerk` for identity and the provider's native header for its credential. Codex retains its dedicated endpoint and requires the override identity header; inspected proxy identity remains Proxy Basic. Legacy `X-Neurwerk-Authorization` and `X-Neurwerk-Credential-Mode` headers are ignored and stripped with header-name-only warnings. Required credentials still must validate, and personal credentials never fall back to global billing.

Use each advertised route's discovery endpoint and fixed credential source. After reconciliation, check default, override, Codex, MCP and proxy requests, discovery list/retrieve, required-credential failures and credential stripping before ending maintenance.

## Recovery

Recovery classification: Forward fix.

Keep maintenance enabled while correcting mismatched callers or service revisions; retain persistent data and credentials.
