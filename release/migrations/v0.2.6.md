# Platform v0.2.6

## Support

- Fresh installation: Supported.
- Supported source versions: None.
- Upgrade from `v0.1.0` through `v0.2.5`: Unsupported.
- Upgrade from unversioned `main`: Unsupported.
- Downgrade: Unsupported.

This release coordinates stable request aliases and opaque reasoning transport
with an exact LibreChat development snapshot. It deliberately provides no
state-transition contract from an earlier platform release.

## Prerequisites

Install the exact CRD and controller prerequisites listed in
`release/manifest.yaml`. Continue to use `stack-setup` package `0.2.10` from
reviewed tooling commit
`fbf91a133e755e5f5b3a79e0e73c2506fc09021f`.

Verify these included `linux/amd64` artifacts before selecting the release:

- `ghcr.io/neurwerk/k8s-stack-pii-engine:0.7.2-cpu`;
- `ghcr.io/neurwerk/k8s-stack-agentgateway-extproc:0.6.3`;
- `ghcr.io/danny-avila/librechat-dev@sha256:909958b41c7035be776aa6a1365016a66007d85fe5cfc8614320e0f24c1810e1`.

The LibreChat image is a reviewed exception for source commit
`14d4f2789d8f1d308713f7acd98fab925f8aa74d`, not permission to consume a
moving development tag.

## Client Actions

Set `GitRepository/k8s-stack.spec.ref.tag` to `v0.2.6` only for an empty target,
while retaining `verify.mode: Tag` and the existing
`k8s-stack-release-trust` reference.

Required client value changes: None.

Required confidential value changes: None.

## Stateful And API Effects

PII Engine uses a hash-keyed namespace for aliases when extProc supplies an
explicit bounded conversation ID. The namespace remains bound to the verified
principal, selected model, and policy version. Headerless requests receive a
new random request scope instead of deriving identity from prompt content.
Reversal material remains request-local and is not persisted.

extProc preserves supported assistant reasoning fields as opaque JSON during
request replay and in buffered or streamed provider output. Reasoning bypasses
PII transformation, placeholder reversal, guard stripping, and notice handling.
Exact Chat and Responses function-argument carriers retain their existing
transformation behavior; unrelated `arguments` keys do not become semantic
content. AgentGateway `1.4.1` remains pinned with wrapper chart `0.7.13` and may
use only the documented metadata-less empty final callback compatibility path.

LibreChat uses configuration schema `1.3.14`, final title generation,
`reasoning_content` replay, Redis-backed resumable streams, and
`STREAM_DELTA_COALESCE_MS=0`. Responses API selection remains disabled. No
upgrade, database migration, or restore claim is made for prior LibreChat state.

## Pre-Deployment Checks

1. Verify the expected cluster context and stable cluster identity.
2. Prove the target K3s datastore, OpenBao Raft storage, Ceph RBD images, RGW
   buckets, and application namespaces contain no state that must be retained.
3. Verify the signed `v0.2.6` tag, generated release manifest, and exact image
   digests and architectures.
4. Confirm the client retains tag-signature verification and the existing
   release trust reference.
5. Confirm AgentGateway remains application `1.4.1` with wrapper chart `0.7.13`.

## Post-Deployment Checks

Inspect both Git sources, all Flux Kustomizations, all HelmReleases, warning
events, and affected logs. Confirm PII Engine, extProc, AgentGateway, and core
LibreChat become Ready. Verify OIDC login, conversation persistence, model
discovery, streamed completion and resume behavior, explicit-conversation alias
reuse, headerless request isolation, opaque reasoning replay, placeholder
reversal, and fail-closed malformed metadata behavior without exposing request
content or Secret values.

## Recovery

Recovery classification: Replacement restore.

A Git declaration revert is not a state rollback. Rebuild a separate empty
environment and restore only through a separately verified component recovery
procedure. Publish a corrective patch for a release defect; never move the
signed tag.

## Exclusions

- Upgrades from every earlier platform release remain unsupported.
- LibreChat Responses API integration remains separate and unsupported.
- LibreChat RAG remains excluded until its deployment-readiness and
  effective-render contracts are complete.
- LibreChat Code Interpreter remains excluded because its first-party runtime
  images have not been released.
