# v0.3.26 upgrade guidance

Stable upgrades are supported; downgrade is unsupported and recovery is
forward-fix. No alpha promotion revisions are declared. Review all crossed release
instructions when upgrading from before v0.3.25. Preserve persistent state and
confirm current independent backups before adoption.

## Prerequisites and activation order

Use standalone `openbao-stack-setup` **0.2.27** from Tooling commit
`550a2f3b52e7baa53ab8a01a59a417c539663235` before adoption. The Tooling runtime
image remains `0.7.4`; it does not contain this workstation CLI. Reconcile the
approved credential catalog with the supported tool, preserving valid credentials
and the existing OpenBao installation. Other prerequisites remain as declared in
the manifest, including ClickHouse Operator `0.0.5`.

Adopt the digest-pinned Studio **0.17.1** API/Web images and compatible Base charts
together before activating the new setup workflow. The new catalog schema is
incompatible with Studio `0.16.4`. Native ContextForge management remains private;
personal OAuth tokens continue to use encrypted PostgreSQL storage while the
OpenBao-backed OAuth limitation tracked in #424 remains open.

## Opt-in Studio MCP Setup

Set `mcp.studioSetup.enabled: true` consistently in AgentGateway, ContextForge,
Studio API and OpenBao values. The shared switch supplies role-based discovery;
keep the legacy named-operator mode disabled. ContextForge setup, trusted-proxy
access, Studio connections and onboarding must remain enabled. Configure the
approved provider egress/SSRF ranges and both Kubernetes API egress lists described
in `charts/contextforge/README.md`.

Switching from chart-owned publication requires a separately approved **clean MCP
cutover**. Old selections, shared credentials and personal provider connections
are not imported. Review retention requirements and authorize their replacement
before activation. Follow the chart's clean-cutover procedure:

1. Prepare isolated shared-key records and scoped Studio/External Secrets roles
   with the exact setup CLI; seed empty records only when absent.
2. After verifying ownership, retire only the selected old native server/gateway
   registrations and obsolete setup projection. If named-operator discovery was
   enabled, explicitly retire its permanent grants/role and obsolete `operator_*`
   keys as documented. Preserve unrelated registrations, databases, PVCs and
   encryption keys; this is not a namespace, database or OpenBao reset.
3. Activate the matching image/chart set and shared switch. Verify bootstrap,
   scoped workload identity, credential delivery and gateway readiness. Bootstrap
   creates empty virtual servers owned by `contextforge-studio`.
4. Administrators enter shared keys again through Studio, reconnect personal
   providers, refresh tools, select tools and Publish. Brave's first setup is
   key-only Publish, then Refresh tools, select tools and Publish; its workload
   waits at zero replicas until a key is configured.

Publish succeeds only after the intended credential version is active and native
membership exactly matches the selection. Managed MCP consumers use no-surge
`RollingUpdate`; Studio checks deployment generation, replica counts and credential
references. Refresh includes the `0.17.1` native camelCase response correction.
Disable clears native membership while retaining the saved selection. Later
bootstrap runs preserve Studio choices. Installations already using `studio-v1`
retain their saved state and do not repeat the initial cutover.

Administrator APIs require `studio-user` and `mcp-admin`. The latter is inherited
by `platform-admin` unless excluded through `authKeycloak.platformAdminRoleExclusions`
and is separately available through `/access/neurwerk-mcp-admins`. Refresh also
requires verified email, `llm:invoke` and the integration's `mcp:<id>:invoke` grant;
it uses the caller's own provider connection and a 120-second native grant.
Refresh sign-in tokens after role reconciliation. Native refresh can change shared
definitions before publication and is not an atomic rollback mechanism.

With `mcp.studioSetup.enabled: false`, the chart-owned publication procedure in
`charts/contextforge/README.md` still applies. Its separate role-based discovery
switches remain opt-in and require an independent setup run after discovery.

## PII NER caching

Engine and model-sync use the verified **0.14.0** image. NER result caching is
enabled by default through `monitorPiiEngine.nerCache`: `enabled: true`,
`maxBytes: 134217728` and `ttlSeconds: 86400`. One accounted-byte budget is shared
across selected languages/models per Engine process. Entries use LRU eviction and
fixed expiry from creation; hits do not extend the 24-hour lifetime. Leave memory
headroom for models, requests and runtime overhead because the budget is not an
exact process-memory limit. Set `enabled: false` to disable caching.

Only NER inference results are cached. CPU rules, custom recognizers and current
policy still run for every request. Cache contents stay in process memory and are
discarded at process exit; existing Valkey data and model-cache PVCs are retained.
Existing NER selectors remain supported as described in `charts/pii-engine/README.md`.

## After authorized adoption

Inspect Flux sources, Kustomizations, HelmReleases, application and database
health, retained PVCs, warning events and bounded logs. For enabled MCP Setup,
verify Refresh, Publish, exact selected tool membership, credential activation and
an authenticated read-only tool call. Accept operator-confirmed feature testing;
deployment health checks still apply. Follow forward-fix recovery rather than
reverting tags as a substitute for restoring persistent state.
