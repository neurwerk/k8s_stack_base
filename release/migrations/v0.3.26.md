# v0.3.26 upgrade guidance

Stable upgrades are supported; downgrade is unsupported and recovery is
forward-fix. No alpha promotion revisions are declared. Existing prerequisites,
database schemas and encryption keys are unchanged. Review all crossed release
instructions when upgrading from before v0.3.25.

## Role-based MCP discovery

First adopt and verify this release's Studio `0.16.4` API/Web images and Base
charts. Then opt in with both `contextforge.setup.adminDiscovery.enabled: true`
and `frontendStudio.api.contextforge.adminDiscovery.enabled: true`; both default
to false. Keep native ContextForge management private.

`mcp-admin` is inherited by `platform-admin` unless removed through
`authKeycloak.platformAdminRoleExclusions`. It is separately available through
`/access/neurwerk-mcp-admins`. The caller also needs `studio-user`, verified email,
`llm:invoke` and the selected `mcp:<id>:invoke` grant. Refresh sign-in tokens after
role reconciliation. No named email/subject or separate discovery login is needed.

If legacy `operatorDiscovery` was enabled, explicitly retire its permanent native
discovery assignments and role, disable that mode, then remove only obsolete
`operator_*` setup-projection keys before enabling the new mode. Setup refuses
migration while the old role ID remains; it does not silently delete grants or
recreate a revoked role. Clients that left the legacy mode off need no identity
migration. Existing accounts, provider registrations and connections are retained.

Verify `admin_discovery_ready=true` and the verified role ID in the generated
Studio setup ConfigMap. An authorized administrator connects their own provider
account and explicitly chooses **Discover tools**. Studio issues only a bounded
120-second team grant and uses that caller's saved authorization for native refresh.
Ordinary Connect, status and invocation requests never renew discovery permission.

After discovery completes, independently rerun the verification-only setup Job
using `scripts/contextforge_setup_job.py` and the procedure in
`charts/contextforge/README.md`. Confirm a fresh `published` status and approved
tools, then separately enable any new client route and verify an authenticated
read-only tool call. The ignored `publishOAuthTools` selector can be removed.
Native refresh can mutate shared tool records before publication and is not an
atomic rollback mechanism. Disconnecting one discovery connection does not erase
the shared catalog; subsequent users invoke with their own connections.

Preserve persistent state and confirm current independent backups. After adoption
and activation, inspect Flux sources, Kustomizations, HelmReleases, application
health, database availability, retained PVCs, warning events and bounded logs.
