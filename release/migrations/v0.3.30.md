# v0.3.30 compatibility

## Support

- Stable upgrades: Supported.
- Supported alpha source revisions: `25ee6c19e0921f78c4cd2e0ffb2c2abf48f9a54c`.
- Downgrade: Unsupported.

Existing installations support a manually prepared upgrade; see the [upgrade note](../../docs/releases/upgrade-0.3.30.md). The declared alpha revision was frozen, signature-verified and successfully reconciled on 2026-10-31.

## Maintenance checklist

- Select add-on definitions compatible with Base 0.3.30, using shared SDK 0.15.8 for release validation and setup 0.8.4 for credential preparation; approve login/logout URLs, gateway permissions and existing directory target groups. Setup includes SDK 0.15.8; runtime provisioner images remain separately pinned.
- Use one maintenance window; follow the [ownership handoff guide](https://github.com/neurwerk/docs/blob/main/dev/operations/upgrades.md#add-on-ownership-handoff), review Helm ownership and Flux pruning, and preserve databases, volumes, Secrets and valid credentials when changing owners.
- For existing legacy LibreChat credentials, use setup 0.8.4's one-time `stack-setup preserve-librechat` command with a verified LibreChat-only selection before normal `stack-setup reconcile`, following the [setup procedure](https://github.com/neurwerk/docs/blob/main/dev/operations/openbao.md). Keep a single credential writer throughout preservation and reconciliation: stop concurrent setup and credential changes. The helper preserves existing keys and records read-back evidence; normal reconciliation then applies the catalog. Do not bootstrap again.
- Expect the shared PostgreSQL/DocumentDB pod to restart when connection and lock settings change; review configured capacity before reconciliation.
- Verify Flux reconciliation, application login, model access and retained data before disabling maintenance, following the [post-deployment checks](https://github.com/neurwerk/docs/blob/main/dev/operations/upgrades.md#after-deployment).
