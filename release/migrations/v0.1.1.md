# Platform v0.1.1

## Support

- Supported source versions: None.
- Supported alpha source revisions: `5a392c5cb4485fb9faef41840c63af1db6aa60fb`.
- Downgrade: Unsupported.

Installation into a verified empty or replacement environment remains supported
as a platform invariant. It is not an in-place upgrade.

## Prerequisites

- For promotion, freeze and successfully reconcile the platform source at
  `5a392c5cb4485fb9faef41840c63af1db6aa60fb` before changing channels.
- Install every prerequisite and CRD version declared in
  `release/manifest.yaml`, including Agentgateway CRDs 1.5.0.
- Authenticate the platform release signer fingerprint independently and
  provision the public `k8s-stack-release-trust` material outside Git.
- Verify required client values, OpenBao-delivered Secrets, storage, DNS, and
  certificates without exposing confidential values.

## Client Actions

For the supported alpha promotion, replace the exact alpha commit source with
signed tag `v0.1.1`, use tag verification with `k8s-stack-release-trust`, set
`platform.neurwerk.com/adoption-mode: upgrade`, set the adoption target to
`v0.1.1`, and record the frozen commit in
`platform.neurwerk.com/promoted-from-alpha`. Review and merge the exact client
commit before allowing reconciliation.

For an empty or replacement environment, select signed tag `v0.1.1` and use
`platform.neurwerk.com/adoption-mode: fresh-install` only after an operator has
verified the target state. Do not attempt an in-place transition from a stable
release because no stable source version is supported.

## Stateful And API Effects

The supported alpha promotion changes the source and trust declaration but no
reconciled platform manifest: the target contains the same runtime content as
the validated alpha commit. Agentgateway remains at 1.5.0, with its 1.5.0 CRDs,
and the pinned PII Engine 0.1.1 and extProc 0.1.2 images preserve standard
streamed usage controls and final usage shapes.

Fresh installation creates the platform's Kubernetes, database, object, and
secret state. The release also includes the Keycloak initial-administrator
required-action email, corrected LibreChat agent and reasoning configuration,
and the K3s Traefik rollout fix. No migration from stable `v0.1.0` is claimed.

## Pre-Deployment Checks

1. Verify the current source resolves exactly to the supported alpha commit, or
   verify that a fresh-install target is empty or is a replacement environment.
2. Verify the published signed tag, release manifest, migration document,
   immutable image pins, declared prerequisites, and time-bounded exceptions.
3. Confirm Agentgateway CRDs are exactly 1.5.0 and do not plan a CRD downgrade.
4. Confirm all enabled Kustomizations and HelmReleases are Ready before changing
   the source declaration.
5. Confirm application-consistent backups and component recovery procedures for
   persistent state even though the supported promotion is runtime-equivalent.

## Post-Deployment Checks

1. Verify the Flux platform source resolves to signed tag `v0.1.1` with tag
   verification enabled.
2. Inspect all Flux Kustomizations, HelmReleases, and non-normal warning events.
3. Verify Agentgateway, extProc, PII routing, streamed usage, and opaque-reasoning
   behavior with authenticated requests and redacted diagnostics.
4. Verify Keycloak, LibreChat, Traefik routing, storage, and secret
   synchronization, then inspect affected logs without exposing sensitive data.

## Recovery

Recovery classification: Configuration revert.

For the supported alpha promotion, restore the client platform source to exact
commit `5a392c5cb4485fb9faef41840c63af1db6aa60fb` with alpha `HEAD` verification,
then reconcile and repeat the post-deployment checks. This reverts configuration
only. It does not downgrade CRDs, reverse database or object changes, or restore
persistent state. Use the affected component's tested recovery procedure or a
replacement restore if state changed or integrity is uncertain.

## Exclusions

- In-place upgrades from stable `v0.1.0` and all downgrades are unsupported.
- LibreChat RAG and Code Interpreter packages remain excluded.
- The time-bounded LibreChat development-image and DocumentDB privilege
  exceptions remain recorded in `release/manifest.yaml`.
