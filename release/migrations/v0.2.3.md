# Platform v0.2.3

## Support

- Fresh installation: Supported.
- Supported source versions: `v0.2.0`, `v0.2.1`, `v0.2.2`.
- Upgrade from `v0.1.0` through `v0.1.3`: Unsupported.
- Upgrade from unversioned `main`: Unsupported.
- Downgrade: Unsupported.

This patch restores the AgentGateway controller's access to Keycloak's public
realm JWKS. The controller resolves the JWKS before pushing fail-closed JWT
policy to the AgentGateway data plane. Keycloak's ingress NetworkPolicy now
admits the exact controller Pod identity in addition to the existing data-plane
identity, without adding a namespace-wide allowance.

## Prerequisites

Install the exact CRD and controller prerequisites listed in
`release/manifest.yaml`. Continue to use `stack-setup` package `0.2.10` from
reviewed tooling commit
`fbf91a133e755e5f5b3a79e0e73c2506fc09021f`.

## Client Actions

Set `GitRepository/k8s-stack.spec.ref.tag` to `v0.2.3` while retaining
`verify.mode: Tag` and the existing `k8s-stack-release-trust` reference.

Required client value changes: None.

Required confidential value changes: None.

## Stateful And API Effects

None. This release changes only the Keycloak ingress NetworkPolicy. It does not
change credentials, APIs, images, databases, persistent volumes, or application
state.

The allowed controller identity is limited to namespace `infra-agentgateway`
and Pod labels `agentgateway=agentgateway`,
`app.kubernetes.io/name=agentgateway`, and
`app.kubernetes.io/instance=infra-agentgateway`. It may reach only Keycloak's
server Pod port `8080` through this rule.

## Pre-Deployment Checks

1. Verify the expected cluster context and stable cluster identity.
2. Verify the signed `v0.2.3` tag and generated release manifest.
3. Confirm the AgentGateway controller uses the exact Pod identity declared
   above.
4. Confirm the client retains tag-signature verification and the existing
   release trust reference.

## Post-Deployment Checks

Inspect both Git sources, all Flux Kustomizations, all HelmReleases, warning
events, and affected logs. Confirm the Keycloak NetworkPolicy admits the exact
AgentGateway controller identity, the controller no longer reports connection
refused while retrieving the realm JWKS, and authenticated LibreChat model
discovery through `/v1/models` succeeds.

## Recovery

Recovery classification: Replacement restore.

A Git declaration revert is not a state rollback. This release has no stateful
effect; publish a corrective patch if the policy does not match the deployed
controller identity. Follow the complete replacement-restore procedure for any
unrelated stateful failure.

## Exclusions

- LibreChat RAG remains excluded until its deployment-readiness and effective
  render contracts are complete.
- LibreChat Code Interpreter remains excluded because its first-party runtime
  images have not been released.
