# Platform v0.2.0

## Support

- Fresh installation: Supported.
- Supported source versions: None.
- Upgrade from `v0.1.0` through `v0.1.3`: Unsupported.
- Upgrade from unversioned `main`: Unsupported.
- Downgrade: Unsupported.

This release replaces dedicated application databases with shared authentication
and operations PostgreSQL services. It deliberately provides no data or PVC
migration from an earlier platform release.

## Prerequisites

Install the exact CRD and controller prerequisites listed in
`release/manifest.yaml`. Verify that every included workload image in the
manifest is available before selecting the release.

Run `stack-setup` package `0.2.10` from reviewed tooling commit
`fbf91a133e755e5f5b3a79e0e73c2506fc09021f`. Reconciliation schema 3 creates the
PostgreSQL namespace policies, roles, records, SecretStores, ExternalSecrets,
and exact application credential copies required by this release.

## Client Actions

Before selecting `v0.2.0`, generate both `client-values` and
`postgres-product-values` ConfigMaps in each of these namespaces:

- `infra-postgres-auth`;
- `infra-postgres-operations`.

Set `GitRepository/k8s-stack.spec.ref.tag` to `v0.2.0` only for an empty target
cluster, while retaining `verify.mode: Tag` and the existing
`k8s-stack-release-trust` reference. Client and platform Git sources do not
reconcile atomically, so publish the ConfigMaps and exact tag selection in the
same reviewed client revision before initial Flux bootstrap.

Required confidential values are generated by `stack-setup`; do not add them to
Git or create them manually.

## Stateful And API Effects

`postgres-auth` owns database `keycloak` and accepts verified-TLS traffic only
from Keycloak. `postgres-operations` owns the DocumentDB database and the Dify,
`dify_plugin`, `dify_vector`, `postgres_langfuse`, and `librechat_rag` databases.
It is a shared application failure and recovery domain.

The operations PostgreSQL canary uses SCRAM authentication over plaintext TCP,
constrained to exact namespace and Pod selectors by NetworkPolicy. Its
DocumentDB gateway requires TLS. The reviewed upstream DocumentDB local image
also requires an object-scoped privilege-escalation exception during startup.

No Keycloak, Dify, Langfuse, LibreChat, Weaviate, FerretDB, or PostgreSQL data
from an earlier release is migrated. Existing PVC contents are incompatible with
this release contract.

## Pre-Deployment Checks

1. Verify the expected cluster context and stable cluster identity.
2. Prove the target K3s datastore, OpenBao Raft storage, Ceph RBD images, RGW
   buckets, and application namespaces contain no state that must be retained.
3. Verify the signed `v0.2.0` tag, release manifest, and every included image.
4. Verify Flux `v2.9.4`, the declared CRDs, and the two PostgreSQL client
   ConfigMap packages are present in the bootstrap source.
5. Verify `stack-setup 0.2.10` is running from the exact reviewed tooling commit.

## Post-Deployment Checks

Inspect both Git sources, all Flux Kustomizations, all HelmReleases, warning
events, and affected logs. Confirm both PostgreSQL releases, provisioning Jobs,
SecretStores, ExternalSecrets, and target Secrets become ready before their
consumers. Confirm Keycloak verifies PostgreSQL TLS, DocumentDB verifies gateway
TLS, and Dify, Langfuse, and LibreChat connect only through their declared
database identities.

Do not print Secret values while validating the deployment.

## Recovery

Recovery classification: Replacement restore.

A Git declaration revert is not a state rollback. Rebuild a separate empty
environment and restore only through a separately verified component recovery
procedure. The shared operations PostgreSQL service must be treated as one
failure domain when assessing recovery consistency.

## Exclusions

- LibreChat RAG remains excluded until its deployment-readiness and
  effective-render contracts are complete.
- LibreChat Code Interpreter remains excluded because its first-party runtime
  images have not been released.
