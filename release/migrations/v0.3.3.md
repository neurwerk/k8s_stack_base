# Platform v0.3.3

## Support

- Stable upgrades: Supported.
- Supported alpha source revisions: None.
- Downgrade: Unsupported.

Fresh installation into a verified empty or replacement environment uses the
canonical defaults normally; no group cleanup is needed. All v0.3.2 prerequisites,
runtime images, package exclusions, and exceptions remain unchanged. Review the
migration and changelog for every crossed release when upgrading from an older
stable tag; this release does not waive their required actions.

## Breaking Changes

The platform owns the 13 `neurwerk-` groups defined in
`charts/keycloak/realm-config/realm-roles/files/standard-access.yaml` as flat
children of `/access`. Application realm roles and composites are unchanged.
Clients own intended memberships, directory settings, and explicit resource
grants, not copies of the platform catalog.

1. Remove `authKeycloak.accessGroups`, `authKeycloak.realmRoles`, and
   `authKeycloak.realmRoleComposites` from client values; even empty overrides are
   rejected. Align group references and directory allowlists with the canonical
   set. Set `authKeycloak.initialAdminGroups` to intended canonical paths (the
   default is `["/access/neurwerk-platform-admins"]`).
2. Ensure effective `openrouterCatalog.grantToAccessGroups` is `false`, including
   any client catalog policy override; `true` is rejected. Under
   `authKeycloak.agentgatewayAccessGroups`, grant `llm:invoke` plus explicit
   `model:<model-id>:invoke` roles only to `/access/neurwerk-llm-all-users`, and
   `llm:invoke` plus explicit `mcp:<server-id>:invoke` roles only to
   `/access/neurwerk-mcp-all-users`. Roles must exist in the effective catalog.
   Other group keys and cross-resource grants are rejected. Application/admin
   membership grants no model or MCP access; resource membership grants no
   application access. `all` does not include future catalog additions.
3. Prepare and render the aligned client values against the target before
   adoption. Apply the client configuration and select the reviewed, published,
   exact signed `v0.3.3` source as separate coordinated changes: the sources do
   not reconcile atomically. Verify both desired revisions and successful
   reconciliation before cleanup; a partial transition is not completion.

For an unused development realm, perform this one-time manual cleanup only after
configuration is aligned. No migration framework or legacy aliases are provided:

1. Verify an independent administrative login that does not depend on groups to
   be removed. Verify canonical groups, intended memberships (especially the
   administrator), and effective application/model/MCP permissions first. If
   active users need preserved access, stop and review their intended memberships
   rather than treating the realm as unused development state.
2. In the intended realm's Keycloak Admin Console, inspect the exact superseded
   old unprefixed access groups, their memberships, and role mappings. Manually
   delete only those groups whose access is no longer needed. Never delete users,
   the realm, `/access`, canonical or unrelated groups, application realm roles,
   composites, or OIDC clients. Removing YAML does not delete existing groups;
   initial-admin provisioning adds missing memberships without removing old ones.
3. Recheck intended memberships and permissions and confirm unrelated identities
   and configuration remain intact. Group deletion removes inherited access, not
   users. Verify Flux sources, Kustomizations, HelmReleases, warning events, and
   affected application logs without exposing credentials or sensitive content.

Release verification is limited to local rendered/static tests and release
contract checks; no live installation, migration, cleanup, or recovery is claimed.

## Recovery

Recovery classification: Forward fix.

Repair client declarations and intended canonical memberships, then reconcile
and verify access again. Do not silently recreate obsolete groups. A source or
configuration revert does not restore deleted memberships or persistent state;
downgrades remain unsupported.
