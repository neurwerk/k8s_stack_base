# Platform v0.1.3

## Support

- Fresh installation: Supported.
- Supported source versions: `v0.1.1` and `v0.1.2`.
- Upgrade from unversioned `main`: Unsupported.
- Upgrade from withdrawn `v0.1.0`: Unsupported; select `v0.1.1` first.
- Downgrade: Unsupported.

This patch adds bounded startup probes for Dify services and datastores,
functional PostgreSQL and Redis health checks, and explicit release ordering
between the plugin daemon and its datastores.

## Prerequisites

Install the exact CRD and controller prerequisites listed in
`release/manifest.yaml`. Verify that every included workload image in the
manifest is available before updating a client.

## Client Actions

Set `GitRepository/k8s-stack.spec.ref.tag` to `v0.1.3` while retaining
`verify.mode: Tag` and the existing `k8s-stack-release-trust` reference.

Required client value changes: None.

Required confidential value changes: None.

## Stateful And API Effects

None. This release changes Dify lifecycle detection and Helm release ordering.
It does not change APIs, databases, OpenBao, Rook/Ceph, PVCs, K3s state, or
stored CRD versions.

## Pre-Deployment Checks

1. Verify the expected cluster context and stable cluster identity.
2. Verify the signed tag and release manifest.
3. Verify all included workload images and their published digests.
4. Confirm that `v0.1.1` or `v0.1.2` is the currently selected platform release,
   or that the target cluster is empty for a fresh installation.

## Post-Deployment Checks

Inspect both Git sources, all Flux Kustomizations, all HelmReleases, warning
events, and the Dify workload logs. Confirm PostgreSQL, Redis, Weaviate, the
plugin daemon, and Dify API become ready without startup or liveness restart
loops.

## Recovery

Recovery classification: Replacement restore.

A Git declaration revert is not a state rollback. Publish a corrective platform
patch for a lifecycle regression. If unrelated stateful effects occur, rebuild a
separate environment and restore only through the affected component's verified
recovery procedure.

## Exclusions

- LibreChat RAG remains excluded until its deployment-readiness and
  effective-render contracts are complete.
- LibreChat Code Interpreter remains excluded because its first-party runtime
  images have not been released.
