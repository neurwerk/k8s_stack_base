## Docling

Adopt the matching Docling, extProc 0.24.0 and gateway charts and client settings from the signed release manifest. The Langfuse rejection-retention worker uses the same extProc image. This Docling rollout does not require maintenance mode.

- Select `docling.enabled` and `docling.mode` in shared client values: `internal` runs official CPU Serve in Kubernetes; `external` uses one complete Serve API elsewhere. Remove the old `docling.inference` settings and mode aliases.
- For external GPU processing, install the manifest's reviewed inference-runtime-manager source, verify the official runtime with cached models and complete the approved conversion benchmark before switching clients. Preserve the existing Docling API key and supply it through `DOCLING_SERVE_API_KEY`; requests use `X-Api-Key`. Retain the previous runtime's image, Compose definition and environment for recovery.
- Select `releases/docling/secret-sync/internal` or `releases/docling/secret-sync/external` under the existing Flux identity. Use the manifest's compatible setup CLI; preserve stored OpenBao records, the API key and its extProc delivery. External mode removes the local Serve workload and obsolete inference-token delivery.
- Set the external URL, matching port and narrow destination CIDRs. Private HTTP requires `allowHttp: true`; HTTPS verifies the server certificate. Optional `docling.ingress.enabled` and `host` expose the authenticated conversion API through HTTPS; arrange matching DNS separately.
- The default cumulative PDF allowance is now **two pages**. Set `documentAttachments.pages` explicitly for larger GPU workloads, such as 250, and configure the external Serve per-document limit to match. Gateway byte/file limits and model context limits still apply; direct Serve calls use the server's own limits.
- Replace `attachments.documents.pdf.mode: native-first` with `extract-text` or an explicitly selected `render-images` policy, and remove `fallback`. PDF image rendering requires a local vision model with PII disabled. Review per-model image delivery while preserving the intended PII settings.

After adoption, verify the signed Flux revision, releases, expected resource pruning, retained application data, warning events and bounded logs. Check document/image processing and missing, invalid and valid API keys. Preserve namespaces, volumes, model caches and rollback material. No database migration is required; follow the manifest's forward-fix recovery policy.
